# 宝可梦 · 弹珠研究所

手机触屏单人弹珠探索游戏，纯静态网页。无需账号、依赖安装、后端、支付或多人服务。

## v4.0 · 传说研究版

### 投球与机关

- 打开即持续多球探索，开关冻结／恢复全部弹珠。投球滑块为 **0.5×–5× 发球数量**，只改变每秒发球数，绝不改变场内重力、弹跳、转环或现有球的运动速度。
- 默认每 0.65 秒投一球，最多 80 球；物理步进固定 120 Hz。普通投球无限，不使用背包中的高级球。切到手机后台暂停，返回后继续。
- 左落点给超梦充能，右落点给洛奇亚充能；每球基础 +125，各自达到 **12500** 后开启捕捉。蓄满保持等待，不自动使用道具；更多充能不会超过上限。
- 底部中间 20 像素窄缝（逻辑宽度 400），每颗落入球独立 **5%** 获得一只非传说精灵；未触发只获得碰撞金币。
- 左上电磁机关真实碰撞每 **30 次**，双侧充能各 +1000，同时产生 100 待收金币，机关计数重新开始。
- 右上精灵信号真实碰撞每 **50 次**，获得一只随机非传说精灵，计数重新开始。
- 中央转环里的黄色小球，每被一颗弹珠首次实际碰到，**必定获得一只随机闪光非传说精灵**。同一颗弹珠不能反复刷取黄球奖励。
- 每颗正常落球产生 5 金币，外加本球碰撞获得的金币。异常卡住超过 24 秒时回收该球，只结算已获金币，不虚构落点或精灵。

### 统一收获

**精灵和金币都先进入待收获区**，不会每获得一只就收入图鉴。点击 **全部收获** 后一次性结算到图鉴和可用金币，不影响自动投球。

待收获按物种和普通／闪光分组，长时间挂机不会生成无限列表。无论是否已领取，奖励、充能、机关计数与背包均每秒自动保存，刷新或导入导出均可恢复。暂未收获的金币不能在商店使用。

### 传说捕捉与道具

- 两只传说为 **超梦（超能力）** 与 **洛奇亚（超能力／飞行）**。
- 充能满后由玩家点击投掷高级球，每次尝试恰好消耗 1 个；普通自动投球不能直接捕获传说。失败保留 12500 充能，成功后该侧归零重新研究。
- 本作初始捕捉率 35%，每失败一次 +15 个百分点，**第 5 次必定成功**。选择投喂蔓莓果时本次额外 +15 个百分点，每次尝试消耗 1 果。成功的传说也进入待收获区。
- 友好商店只卖道具：高级球 800 金币、蔓莓果 200 金币、神奇糖果 2400 金币。高级球是 Ultra Ball，不与超级球（Great Ball）混淆。
- 神奇糖果使用后研究伙伴提升 1 级，每级左右落球充能 +25，最高 Lv.5（每球 225）。满级不会再消耗糖果。
- 首次升级至 v4 获赠高级球 ×3、蔓莓果 ×1；新存档另有 800 金币。旧版现有金币与收藏不变，不重复发放升级礼包。
- 随机非传说池按常见 62%、特别 30%、稀有 7.5%、幻之梦幻 0.5% 分层抽选，池内均匀。常规精灵基础闪光率 1/4096，黄球奖励保证闪光；超梦和洛奇亚只可通过专属捕捉获得。

物种、分类、道具中英文名与资料参考 [PokeAPI 物种资料](https://github.com/PokeAPI/pokeapi/blob/master/data/v2/csv/pokemon_species.csv)、[道具资料](https://github.com/PokeAPI/pokeapi/blob/master/data/v2/csv/items.csv)及[本地化名称](https://github.com/PokeAPI/pokeapi/blob/master/data/v2/csv/item_names.csv)。高级球捕捉与神奇糖果升级借鉴宝可梦设定；蔓莓果捕捉加成借鉴 Pokémon GO。机关充能、研究等级收益、糖果价格、具体捕捉率及保底是本作规则，并非正作的完整捕获公式。

## 手机发布

仓库 `JustinZheng0518/Pokemon` 的 `main` 分支：

1. **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
2. 每次推送自动运行 **Deploy GitHub Pages**。规则测试通过后才发布，必须显示绿色成功。
3. 手机打开 `https://justinzheng0518.github.io/Pokemon/`，确认页头显示 **v4.0 传说研究版**。iPhone 可通过 Safari「分享 → 添加到主屏幕」。

CSS 和脚本使用版本地址，避免旧版缓存；如果没有新版版本号，请在部署成功后刷新。

## 本地开发与验证

在现有仓库目录运行，无需安装依赖：

```sh
python3 -m http.server 8000 --bind 0.0.0.0
```

规则测试使用 Node.js 24：

```sh
node --test tests/*.test.cjs
```

核心规则在 `game-core.js`，独立于 DOM 与动画时钟，支持在 Node.js 中测试概率边界、落点充能、奖励合并、捕捉消耗和存档。页面与固定步长物理在 `game.js`。

## 存档与资源

- 沿用 `pocket-field-v1` 浏览器存储键，内容升级为第 2 版；自动迁移原有收藏、闪光数量、金币和速率。待收获、背包、双侧充能及捕捉失败次数一并保存。
- 支持 JSON 导入导出。导入前先暂停，并建议导出备份。无效存档会被拒绝，读取异常不会自动覆盖原存档。
- 不同手机／浏览器不会自动同步，清除浏览器数据会丢失进度。没有服务器上传。
- 地图 `assets/town.svg` 为本项目绘制的像素风城镇，参考用户提供的视频重新设计，未直接截取录像；物理参数为视觉近似。
- 精灵像素图来自 [PokeAPI/sprites](https://github.com/PokeAPI/sprites)，随站点发布，不需要第三方图片服务器。没有服务工作线程或离线缓存。
